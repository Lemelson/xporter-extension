# Search completion fixtures

`search-endings.synthetic.json` contains constructed regression cases, not captured X responses. It checks that missing cursors, partial instruction sets and alerts cannot become successful empty exports. An explicit `TimelineTerminateTimeline` with `direction: Bottom` is accepted as terminal. The separate live fixture below covers the observed cursor-only ending.

Live protocol compatibility remains unverified. In particular, this policy may leave a genuinely finished search with `SEARCH_END_UNCONFIRMED` if X omits an explicit terminal marker. Saved rows remain downloadable. Do not reintroduce absence-of-cursor or date-coverage completion merely to hide that state.

Before release, obtain redacted responses from an authorized ordinary browser session for: a confirmed empty Latest search, a final page of a nonempty search, a continuing page, and `TimelineShowAlert` (including any accompanying entries). Preserve instruction types, ordering, cursor structure, error shape and response status; remove credentials, request headers, account identifiers and post content. Record observed UI state and capture date alongside each fixture. Do not label constructed or third-party examples as live captures. Add a protocol-specific terminal rule only when these responses support it.


`search-empty.live.json` was captured from native Helium Latest search on 2026-09-06 for `(from:strndstein) since:2000-01-01 until:2000-01-02`: HTTP 200, 720 bytes, and native UI “No results”. It contains exactly two typed cursor entries and no rows or termination instruction. A separate broad `(from:strndstein)` search returned rows with the same `cursor-bottom-0` ID and then fetched another page on native scroll. Thus only the complete cursor-only shape is accepted; bottom ID, filtered row count and short pages alone are insufficient. Opaque cursor values are redacted; all instruction, cursor type, entry ID and sort-index fields are preserved. No request headers or credentials are included.

`search-empty-pagination.live.json` was captured on the same date from the Bottom-cursor request following the four-row September 4 export (guard query since September 2 until September 6). HTTP 200 returned no rows and two `TimelineReplaceEntry` instructions for the Top and Bottom cursor entries. The native UI stayed at its last post. Opaque cursor values are redacted. The worker verifies the request cursor matches the previously accepted Bottom cursor before this empty ending can complete an export; an empty Top refresh cannot do so.
