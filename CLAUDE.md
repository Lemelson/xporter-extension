## September 29 review contracts

- Generic post, bookmark and user-list pages carry `partialError` when X returns usable rows beside errors. The worker commits those rows, reports the classified error and retains the request cursor for a deduplicated Resume; a partial page never certifies completion.
- Stop cancels discovery and authenticated requests across pending cookie, native-template and endpoint-cache reads. Resume requires readable saved dedup batches. Posts/bookmarks check Stop between batch writes; detailed user lists apply a changed quantity limit before appending each row.

- Download diagnostics settle interrupted generation as `unknown/WORKER_RESTART` and a missing browser record as `unknown/TRACKING_LOST`; handed-off downloads still reconcile against browser state.
- Checkbox tick strokes use physical borders so the symbol stays a check in RTL; layout still follows logical direction.
- Detailed review and verification: `reviews/2026-09-29.md`. Existing version 2.0.2 is retained for this local review branch.

**XPorter** — a Chrome **Manifest V3** extension (vanilla JS, **no build step, no dependencies**) that exports X/Twitter posts, personal bookmarks, followers, following, and verified followers to **CSV / JSON / XLSX / TXT**, using X's internal GraphQL API through the user's own logged-in session.

- **Local version:** 2.0.2 (`manifest.json`). A local verification or ZIP does not establish the published Chrome Web Store version.
- **Run it:** `chrome://extensions` → Developer mode → *Load unpacked* → this folder. No npm, no compile.
- **Deep docs:** read **[`agent.md`](agent.md)** for the full architecture/reference. `README.md` is the user-facing doc.

## Gotchas that bite

1. **Two i18n systems:** `popup/locales/` = in-app strings; `_locales/` = Chrome Store metadata. Don't confuse them.
2. **Adding a setting or string → update ALL 14 `popup/locales/*.json`** (add to `en.json` first). Settings need a default only in `utils/storage.js`; defaults are applied on read, without an install-time snapshot write.
3. **Cross-world capture contract:** `utils/capture-contract.js` and `utils/native-request-template.js` load in MAIN; their generated `content/capture-prerequisites.js` bundle loads first in the isolated world. Distinct resource paths avoid Chromium cross-world script deduplication. Run `node scripts/check-capture-bundle.js --write` after canonical prerequisite edits; the deterministic gate rejects stale bundles. Each world still validates at its own trust boundary.
4. **Single UI:** user-facing export controls live in `popup/`; keep popup status rendering in sync with the worker protocol.
5. **Help tooltips** (`!` icons) support `**bold**` markup for the "gist" — keep both `**…**` spans when editing/translating; aria-labels are auto-stripped (`renderHelpMarkup` / `stripHelpMarkup` in `utils/shared.js`).
6. **X API is fragile:** 400s usually = a changed GraphQL **feature flag** (`utils/api-features.js`); queryIds drift (auto-discovered + live-captured, with `FALLBACK_ENDPOINTS` to refresh). Use `encodeURIComponent`, never `URLSearchParams`.
7. **Service worker can be killed mid-export** — persist after every page. Stop, terminal cleanup, and a fresh run must abort/clear all three active limiter slots, not only the primary limiter.
8. **Queued storage mutations:** never bypass `XPorterStorage.saveSettings()`, the queued history mutations, or the usage mutators with a new load→modify→save path; concurrent handlers would lose updates.
9. **Current downloads are transactions:** reserve the starting lock before the first async snapshot read; do not reload mutable state/settings or re-check photo permission between parts. Reuse the frozen transaction and its byte-bounded LRU photo cache; in-flight URLs share a promise, settled entries may be evicted, and preview fetch/body reads must retain their abort and byte bounds.
10. **Date-range posts** use a separate path: open an X **search tab** and scroll it; the user must keep it open. Local calendar bounds and a persisted launch-time cutoff filter padded search results. Versioned state prevents UTC-era date Resume from mixing semantics: old/unknown date states require a new export while saved rows stay downloadable. Only explicit bottom termination or the captured cursor-only empty page proves source completion under the conservative parser policy; rows beside partial GraphQL `errors` are kept, but the whole search remains unconfirmed even after a later clean terminal page; a clean Resume replay can restore completeness. Unknown instruction types are filtered before both parsing and terminal detection. Other cursorless endings are unconfirmed pending live fixtures. Retry limits live in `XPORTER_CONFIG.SEARCH_CAPTURE`. See `agent.md` §5.
11. **`tweetCount`/`tweetBuffer`** mean item count/buffer even for user exports (historical naming).
12. **CSS:** never hardcode colours — everything is CSS custom properties with `dark`/`light` (`.light` on `<body>`).
13. **Rate-limit budgets are endpoint-specific:** use `XPorterAPI.getRateLimit(operationName)` and never reuse one operation's headers for another. Header-less responses must take the mode-specific fallback path.
14. **Deterministic proof has a boundary:** `test-all.js` proves repository contracts, not current authenticated X behavior. Query IDs, feature flags, cookies, and live response shapes require separate authenticated live-X verification.
15. **Large downloads are multipart:** never call `loadAllTweets()` for the current export download path. `downloads.js` reads bounded batch ranges and uses `DOWNLOAD_PART_LIMITS`; XLSX/JSON/CSV/TXT parts must remain below their configured row ceilings. Embedded-photo XLSX parts use bounded previews and report `photos` plus `building_xlsx` stages.
16. **Post types are explicit and feed plans are resumable:** originals/quotes/articles use `UserOriginalsTimeline`; selecting reposts upgrades that pass to `UserTweets`; replies-only uses `UserRepliesTimeline`. Replies mixed with any other selected type use the one-pass `UserTweetsAndReplies` timeline and filter exact row types locally, matching the pre-1.6.1 request surface. Filter combined rows by the parser's non-exported stable author ID before display-field fallback, persist `postFeedPlan`/`postFeedIndex`, keep foreign parent rows only as nested context, and never reuse a cursor across feeds.
17. **Cursor de-duplication is bounded:** ordinary posts/user-list exports keep only `RECENT_EXPORT_ID_LIMIT` IDs in memory. Do not restore an unbounded per-run `Set`; date-range search is the separate path that needs full saved-ID de-duplication on resume.

18. **Popup form ownership:** never scrape photo radios, language/theme/mode, or unconfirmed retry values into the ordinary form save. Persist the accepted retry value, including while a new number is being typed before blur. Photo permission remains in the initiating click; a generic autosave must not persist an unconfirmed choice. Quantity presets come from the actual select options; old 5,000/10,000 settings use Custom.

## September 22 verification contracts

- GraphQL errors are classified as rate limit, authentication, stale query or transient failure. Empty/nested-null result envelopes with errors are not successful empty exports. Accepted partial timeline rows are preserved. Date search uses the same classifier, including HTTP 200/code 88; HTTP reset timestamps are honored within the user wait budget.
- Stop during a batch write leaves an unfinished page resumable; neither a terminal response nor a next cursor may skip unread rows. Date Resume replays and deduplicates; user-list Resume preserves its current page cursor.
- Settings and export-state reads fail with `STORAGE_READ_FAILED`; callers must not replace unreadable stored data with defaults, empty exports or expiry decisions. Startup catches this failure without clearing the existing badge/data.
- XLSX data sheets have one frozen header row and optional Profile/Media sheets. XML strips invalid characters, keeps long IDs as text, and marks cells truncated by Excel's length limit. Async generation uses DEFLATE for XML, falls back to STORE, and observes both compression-stream promises. Current multipart downloads determine columns across all parts before serialization.
- Native request capture normalizes relative fetch/XHR URLs before relaying; SearchTimeline bodies are captured only on search pages. Endpoint discovery preserves good per-operation results and remembers absent operations for the cache lifetime.
- Release ZIPs keep only the root manifest and runtime emoji font/licensing assets; source PNGs and nested build manifests are excluded. `scripts/test-xlsx-export.js` runs through the download-transaction suite. Browser review scenarios are in `scripts/test-popup-review-fixes.mjs` and use disposable profiles.

Popup recovery: initial status read failure blocks Start, mode changes and New Export until a readable snapshot arrives; a translated error is shown and visible-popup polling retries. Mode changes roll back mode and format if clearing fails. Ordinary saves serialize their diff against the updated settings cache; pagehide/visibility flushing sends the final edit even during an in-flight write. Deleted history entries are removed from the localization cache. `test-popup-review-fixes.mjs` covers these paths. The language menu is bounded to the header and visible shell at narrow widths/short heights; tab arrow navigation follows RTL. `test-popup-menu-layout.mjs` covers extreme menu geometry and long mode labels.
