## Подтверждённые проблемы и исправления

### 1. P2 — временная ошибка записи удаляла содержимое истории

Место: [`utils/storage.js`](../utils/storage.js), `saveExportHistory`.

Сценарий: история содержит сохранённые строки; запись новой выгрузки один раз завершается временной I/O-ошибкой, затем записи снова работают. Код считал любой отказ переполнением квоты, удалял `items` у всех записей и повторно сохранял только метаданные. Успешная повторная запись необратимо лишала старые выгрузки скачиваемых данных.

Исправление: удаление payload допускается только для распознанной ошибки квоты. При остальных ошибках операция возвращает отказ и сохраняет предыдущую историю. Следующая операция в очереди продолжает работать. Настоящий quota fallback сохранён.

Проверка: `test-storage-concurrency.js` воспроизводит временный отказ, сохранность старых строк, восстановление очереди и отдельный случай `QUOTA_BYTES`.

### 2. P2 — неудачное удаление просроченных данных позволяло их скачать

Место: `utils/storage.js`, `pruneExpiredExportHistory`; маршрут `DOWNLOAD_HISTORY_ENTRY`.

Сценарий: данные истории уже просрочены, но запись очищенной истории отклоняется. Функция сообщала об успешной очистке, маршрут повторно читал старые строки и передавал их в скачивание, нарушая выбранный срок хранения.

Исправление: отказ записи порождает `STORAGE_WRITE_FAILED` до загрузки и передачи history-файла браузеру. Повторная успешная очистка остаётся возможной.

Проверка: regression с настоящим модулем downloads подтверждает отсутствие вызова `chrome.downloads` после неудачной очистки и последующее восстановление очереди.

### 3. P2 — Resume игнорировал ошибку чтения сохранённых ID

Место: [`background/service-worker.js`](../background/service-worker.js), `preloadSeenIds`.

Сценарий: сохранена строка `1`, страница при Resume содержит `1,2`, лимит равен двум. Чтение сохранённого batch завершается ошибкой. Best-effort catch скрывал отказ: повторная строка `1` занимала оставшееся место и вытесняла нужную строку `2`.

Исправление: чтение ID для Resume обязательно. Отказ останавливает replay до новых запросов/записей, сохраняя данные и текущую страницу.

Проверка: lifecycle regression требует `STORAGE_READ_FAILED` и сохранность прежних строк.

### 4. P2 — Stop во время записи batch продолжал обработку постов и закладок

Место: `background/service-worker.js`, `_fetchPostTimelineLoop`.

Сценарий: страница содержит две строки, запись первой уступает управление; приходит Stop. Цикл постов/закладок всё равно добавлял вторую строку и мог передвинуть cursor либо показать завершение. Существующие тесты такого Stop покрывали поиск по датам и списки пользователей, но не эти два режима.

Исправление: проверка `running` между строками и после промежуточной записи. Недочитанная страница остаётся на request cursor; Resume повторяет её и убирает дубликаты. Полностью обработанная чистая последняя страница по-прежнему может корректно завершиться.

Проверка: расширенная lifecycle-матрица проверяет posts/bookmarks/date/followers, null и непустой следующий cursor, Stop и реальный Resume с итоговыми ID `1,2`.

### 5. P2 — частичный ответ X ошибочно считался полной страницей

Место: [`utils/api.js`](../utils/api.js), generic timeline/list функции; обе generic worker-петли.

Сценарий: HTTP 200 содержит полезные строки вместе с GraphQL/REST `errors`. При наличии строк API скрывал ошибки. Отсутствие нижнего cursor становилось `source_exhausted`; наличие cursor позволяло перейти дальше, пропустив недоставленные строки.

Исправление: API возвращает классифицированный `partialError` вместе со строками. Worker сначала сохраняет строки, затем сообщает ошибку, сохраняя request cursor и возможность повторения страницы. Частичный ответ не подтверждает полноту источника.

Проверка: API fixtures с ошибками и null/непустыми cursors; полноценный worker сценарий launch → сохранённый error → Resume → complete для posts/bookmarks/followers с первой страницей на null cursor. Итоговые строки не дублируются.

### 6. P2 — после Stop могли запускаться discovery и авторизованные запросы

Место: `utils/api.js`, `discoverEndpoints`, `withStaleRetry`, GraphQL/REST auth-подготовка.

Сценарий: Stop отменяет discovery fetch, но catch превращает отмену в fallback success, после чего стартует новый запрос. Другой вариант: Stop приходит во время чтения endpoint-кеша или native request template; после завершения чтения код входит в новую discovery-попытку.

Исправление: монотонная cancellation epoch проверяется через асинхронные границы чтения кешей, cookies, discovery и контекста подписанного запроса. User Stop возвращает `ABORTED`; deadline discovery сохраняет предусмотренный fallback.

Проверка: отдельно отмена активного fetch, задержанное чтение endpoint-кеша и native template. После отмены активного fetch нет последующих запросов; при Stop во время чтения кеша число сетевых запросов равно нулю.

### 7. P2 — уменьшенный лимит не соблюдался во время About enrichment

Место: `background/service-worker.js`, `appendUsersToExport`, `enrichUsersWithAboutDetails`.

Сценарий: для страницы выбраны три пользователя при лимите три. Во время медленного About запроса пользователь уменьшает лимит до одного. Выбранный заранее список всё равно сохранялся целиком; в настоящем режиме превышение могло достигать размера страницы.

Исправление: перед добавлением каждой строки и запуском следующего About batch проверяется текущий лимит. Частично использованная страница сохраняется для продолжения.

Проверка: смена лимита 3 → 1 внутри About запроса сохраняет одну строку; Resume +2 получает оставшиеся строки ровно один раз.

### 8. P2 — старые history-выгрузки падали при TXT/XLSX

Место: [`utils/csv.js`](../utils/csv.js), `selectedPostTypeLabels`.

Сценарий: старая запись истории не имеет snapshot `postSelection`. Downloads передаёт `null`; default argument `{}` не заменяет явный null. TXT и XLSX с Profile sheet выбрасывали TypeError.

Исправление: null-safe проверка отсутствующего snapshot. Данные выгружаются; информация о выбранных типах не выдумывается.

Проверка: реальные `downloadHistory` для TXT и XLSX, сохранённый текст, Profile sheet и отсутствие искусственного списка типов.

### 9. P2 — быстрое переключение языка смешивало UI, форматирование и сохранённый язык

Место: [`popup/popup.js`](../popup/popup.js), `selectLanguage`.

Сценарий: медленно загружается русский язык, затем пользователь выбирает немецкий. Promise первого выбора завершается позднее: UI и сохранённая настройка становятся русскими, а `currentLang` остаётся немецким.

Исправление: выборы языка последовательно выполняют render и persist. Ошибка первого сохранения не блокирует следующий выбор.

Проверка: задержанные операции ru → de, порядок render/save, согласованность итогового языка; отдельный отказ первого save и успешный второй выбор.

### 10. P2 — пропавшее сообщение скачивания навсегда блокировало popup

Место: `popup/popup.js`, `refreshDownloadPlan`, safety polling, download click.

Сценарий: при терминальном экспорте теряется `DOWNLOAD_COMPLETE`/`DOWNLOAD_ERROR`, например при перезапуске worker. Popup не опрашивал терминальное состояние и сохранял busy: Download, формат, режим, Resume и New Export оставались заблокированными до повторного открытия.

Исправление: видимый busy popup сверяет состояние с authoritative download plan. Неактивный план снимает блокировку; подготовка запроса и активная операция сохраняют её. Poll выполняется по одному, чтобы ответы медленнее интервала не обесценивались новыми запросами. Последняя деталь добавлена после перекрёстной проверки самого исправления.

Проверка: inactive/active/preparation состояния, задержанный plan response и disposable Helium сценарий с отсутствующим terminal broadcast.

### 11. P2 — старые ответы сохранения формата откатывали более новый выбор

Место: `popup/popup.js`, output-format change.

Сценарий: пользователь выбирает XLSX, затем JSON. Поздний отказ первого save откатывал отображение к CSV после успешного JSON. Поздний успешный ответ также мог сделать кеш XLSX при показанном и сохранённом JSON; следующий отказ использовал неверный кеш для rollback. При переключении на Followers во время сохранения TXT режим мог остаться настроенным на неподдерживаемый TXT при показанном CSV.

Исправление: транзакции формата сохраняют захваченный выбор последовательно; нормализация формата при переключении режима использует ту же очередь. Rollback UI относится только к последнему выбору. Кеш, сохранённая настройка и формат следующего Download согласованы.

Проверка: задержанные старые failed/successful replies, следующий отказ последнего выбора, корректный rollback к последнему подтверждённому формату и pending TXT → Followers с итоговым CSV.

### 12. P2 — диагностика скачивания навсегда оставалась generating после смерти worker

Место: [`utils/diagnostics.js`](../utils/diagnostics.js), `recover`.

Сценарий: begin → привязаны download IDs → worker погиб до `download_handoff`. Даже если браузер затем сообщал о завершении всех файлов, запись оставалась `generating`, поскольку `handedOff` никогда не становился true.

Исправление: незавершённая генерация при восстановлении получает терминальное `unknown/WORKER_RESTART`; orphan bindings удаляются. Настоящие handed-off операции продолжают сверяться с браузером. Повторное восстановление и поздние completion events не создают ложный успех и не считают операцию дважды.

Проверка: restart с IDs и без IDs, повторный recover, поздние события, сохранённая нормальная handed-off операция.

### 13. P3 — отказ сохранения формата оставлял неверные связанные контролы

Место: `popup/popup.js`, output-format rollback.

Сценарий: выбор XLSX не удалось сохранить, select вернулся к CSV, но XLSX photo options оставались видимыми; аналогично мог устаревать TXT hint.

Исправление: rollback повторно применяет весь layout выбранного режима/формата.

Проверка: отказ XLSX save восстанавливает CSV и все зависимые контролы, а не только select.

### 14. P3 — удалённая запись browser download оставалась pending в диагностике

Место: [`background/download-diagnostics.js`](../background/download-diagnostics.js), `reconcile`; `utils/diagnostics.js`.

Сценарий: запись download history удалена, пока worker спал. Успешный `chrome.downloads.search({id})` возвращает пустой массив. Код его игнорировал, оставляя диагностическую операцию handed_off/pending без возможности завершения.

Исправление: успешный поиск без записи приводит к `unknown/TRACKING_LOST` и удалению multipart bindings этой операции. Ошибка самого поиска остаётся retryable и не трактуется как пропавшая запись.

Проверка: пустой search, multipart поздние события, idempotent counters, thrown search и успешная сверка при следующей попытке.

### 15. P3 — выбранные чекбоксы в RTL показывали стрелку вместо галочки

Место: [`popup/popup.css`](../popup/popup.css), псевдоэлементы выбранных `post-choice` и `post-type-choice`.

Сценарий: на арабском Home синяя отметка выглядела как `>`, тогда как EN/RU показывали галочку. Рисунок использовал логическую `border-inline-start`; в RTL эта рамка переходила направо, но поворот оставался прежним. Ошибка обнаружена основной визуальной проверкой снимков, после автоматических layout-проверок.

Исправление: рамки, рисующие сам символ, имеют физическую ориентацию, независимую от направления текста. RTL-порядок элементов сохранён; XLSX radio-mark не изменён.

Проверка: исходный `localized-copy/ar-dark-home.png`, повторная отрисовка арабского экрана после исправления в `localized-copy-ar-after/ar-dark-home.png` и сравнение галочек основным агентом. Отдельный unit-тест, повторяющий CSS-declaration, не добавлялся для этой небольшой визуальной правки.

## Ограничения доказательств

В этом запуске не выполнен экспорт из авторизованного живого X-аккаунта. Поэтому текущие private endpoint, cookies, query IDs и реальные payload всех режимов требуют отдельной live-проверки. Временные профили не использовали пользовательский аккаунт и production feedback.

Проверка выполнена на macOS/Helium. Реальные Windows и Chrome 111 не проверены этим запуском. Развёрнутые Chrome Web Store, Pages и Apps Script не проверялись как результат этой локальной ветки. Версия manifest остаётся 2.0.2; публикация релиза не является результатом ревью.
